# Synthetic runtime seeds

Optional Backend Python examples for sandbox seed import and synthetic smoke tests. Users can enter their own JD and define a dynamic rubric; these files do not restrict supported roles. The v3 pair is the current sandbox seed only and remains unapproved; importing it creates a draft and never bypasses the existing approval gates.

- `jd-backend-python.vi.md` and `rubric-backend-python.v1.json`: preserved v1 reference.
- `jd-backend-python.v2.vi.md` and `rubric-backend-python.v2.json`: preserved v2 draft/unapproved review snapshot.
- `jd-backend-python.v3.vi.md` and `rubric-backend-python.v3.json`: current draft/unapproved sandbox seed, containing AI-proposed values pending source verification; no authenticated HR–IT joint decision record was found in the worktree. Used by deployment smoke and rubric seed import.
- `interview-question-bank.v1.json`: unapproved question-bank seed.

v1 and v2 files are preserved. Seed imports still require normal workflow review/approval; v3 does not grant approval, allow publication, or enable assessment of real applicants. Real CVs and applicant records never belong in this directory.
